      How to do each step

      Launching early is fine. Every push redeploys, and Google starts finding the pages sooner.

      1. Connect the repo in Netlify

        Each site is a Netlify site linked to its GitHub repo (proj1 to proj5). Each repo has a netlify.toml that publishes only the site folder and sends the security headers, so the private notes stay private. Every push from the loop goes live within a minute. Already done for all five.

      2. The free address

        The Netlify site name is the address: powerstationruntime.netlify.app, clearpoolmath.netlify.app, yarnsums.netlify.app, quiltcalculators.netlify.app and mathtank.netlify.app (proj1 to proj5). Every page points Google at that address, so never rename a Netlify site without telling Claude Code first. Already done for all five.

      3. Add it to Google Search Console

        At search.google.com/search-console, add a URL prefix property for the free address, such as https://yarnsums.netlify.app/, and choose the HTML tag method. Paste the tag to Claude Code, which adds it to the home page and pushes. Then click Verify. Search Console shows real search numbers, which the build can't measure.

      4. Submit the sitemap

        In the verified property, open Sitemaps and submit sitemap.xml. Claude Code can read the sitemap status (shown on each site card), but its connection can't submit. Done for all five on October 6. Google re-reads the sitemap by itself as the loop adds pages.

      5. Later: buy the real domain

        Not needed to rank. When there's budget, buy the domain of the site with the most Search Console impressions first (a .com is about $10–11 a year at Cloudflare or Porkbun). Claude Code then moves the site over with permanent redirects, so it keeps its rankings.

      6. Turn off a routine when its site is finished

        Each site builds 5 rounds of about 10 pages, and the control room starts each next round by itself. After round 5 the site shows "Finished" and its routine keeps waking up and doing nothing. Turn it off at claude.ai/code/routines. A finished site leaves a DONE.md file with a summary and the 10 best pages to build next.

      7. Optional: give the builds full web access

        The cloud sandbox blocks most websites, so the builds verify facts from search results instead of reading the source pages. In claude.ai/code, set the Default environment's network access to Full so they can read the sources directly.

      8. Keep an eye on usage

        The routines use your plan's five-hour usage limit, the same one Claude Code on your laptop uses. When it is hit, runs fail until it resets, then carry on. Credit sessions use the one-time $100 cloud launch credit instead (expires November 5). Pay-as-you-go is off, so nothing is charged to your card. Check claude.ai/settings/usage now and then. Pausing a routine is safe: the next run picks up exactly where the last one stopped.

      What happens in every run

      Each site, every hour, in a fresh cloud session with no memory of the last one

      1. Wake upA cloud routine starts Claude with the site's GitHub repo.
      2. Read the notes.ai/task.md says what's done, what's next and what failed before.
      3. Build one pieceA calculator, a page or a sourced data file.
      4. Test itSEO, content quality, security and math checks, then phone and laptop browser tests.
      5. Get a reviewA second AI looks for the three most likely ways it's wrong for a visitor.
      6. PublishPush to main. Netlify puts it live within a minute.
      7. RepeatBack to "Build one piece" until 40 minutes have passed.
      8. Hand offUpdate the notes for the next run, then stop.

      The work is split into 5 rounds of about 10 pages. A round ends with DONE.md, which lists the 10 best next pages; every 3 hours the control room routine turns that list into the next round, up to round 5. A round gets at most 30 runs. A credit session (paid from the $100 launch credit) runs the same loop non-stop and puts a lock in the repo, so the hourly routine stands down until the session ends. A run whose tests fail publishes nothing and records what went wrong.

      Why these five sites

      From the research session on October 6, 2026

      By 2026, every simple calculator niche already has 5 to 10 AI-built sites. Most have a few thin tools with fixed assumptions and unsourced numbers, and few are updated after launch. Rather than avoid crowded niches, these sites aim to be the most complete and most correct one in each.

      That comes down to three things: depth (every tool and question in the niche, linked together), verified numbers (each formula unit-tested against a cited source) and honest pages (no fake reviews, real safety notes). Each niche below has steady hobby or home-owner searches, many separate questions that each deserve a page, and weak current results.

      What the builds will never do

      • Spend money, sign up for anything or create accounts
      • Add API keys, ads, analytics or tracking. You add those later.
      • Copy text, images or code from competitor sites
      • Force-push, rewrite git history or touch anything outside the repo
      • Publish the private files (instructions, notes, research). Only the site/ folder goes live.
      • Push without passing tests and a review

      Known limits

      • No search volumes. The Semrush connector had 0 API units, so the build order follows usefulness, not measured demand. Search Console will show real numbers after launch.
      • Most websites are blocked in the cloud sandbox. A fact is used only if a search result from the source states it or two reputable sources agree. Anything else is left out.
      • This dashboard refreshes itself every hour at :50 from your laptop (Windows task CompoundingLoopDashboard) while the laptop is on and you're signed in. The repos are private, so the page can't read GitHub directly. Times, countdowns, locks and the schedule are recalculated in the page every 30 seconds. Ask Claude Code to "refresh the dashboard" for an immediate update.
      • Google is slow at first. All five sites are verified in Search Console and their sitemaps are sent. Indexing a new site usually takes days to weeks. Each card shows whether Google has indexed the home page, plus clicks and views for the last 28 days (Search Console data lags 2–3 days).

      Security setup

      • Strict security headers on every page: same-origin scripts only, no inline scripts or iframes, no framing by other sites
      • A scan for leaked keys and secrets on every test run
      • Netlify publishes only each repo's site folder. The tests fail if that setting changes, and every dashboard refresh checks that the private notes return 404 on the live address.
      • No third-party scripts and no runtime packages, so there's no supply chain to attack
      • GuardVibe and Snyk were considered. GuardVibe targets full-stack apps and Snyk needs an account, so neither adds much for static sites.

      Ideas for keyspersecond.com

      • Stats pages from your PostHog data, such as "what's a good keys-per-second score?" with real percentiles nobody else has
      • Translated versions of the main pages for the biggest non-English audiences
      • Related tools on the same domain (click speed, reaction time, typing tests) to capture neighbouring searches
