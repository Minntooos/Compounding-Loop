On Windows: (1) run Vitest from a cwd whose drive letter is uppercase (PowerShell `Set-Location C:\...`); Git Bash's `/c/...` gives `c:` and Vitest loads twice, "failed to find the runner". (2) Freshly written temp files can be briefly locked (EBUSY) at cleanup: pass `maxRetries` to `rm`/`rmSync`. (3) Spawning git is slow under a full parallel run, so wait for a signal (e.g. `onPoll`) instead of a fixed sleep. (4) The temp folder may sit inside a git repo (a home folder kept in git); tests that need "not a repo" set `GIT_CEILING_DIRECTORIES`.
