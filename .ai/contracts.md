# HTTP API contract (server ⇄ web)

Owned by the **server** lane; change it in the same commit as any route change. **web** may append under "Requested". Base path `/api`, JSON unless noted. Types live in `src/core/types.ts`.

| Method | Path | Returns | Notes |
|---|---|---|---|
| GET | `/api/health` | `{ ok: true, version, demo: boolean }` | liveness |
| GET | `/api/loops` | `LoopSummary[]` | Fleet; sorted by attention (failing, blocked, building, waiting, done) |
| GET | `/api/loops/:id` | `LoopDetail` | summary + timeline (commits), contract (done-when items with pass/fail), knowledge, decisions |
| GET | `/api/inbox` | `InboxItem[]` | every BLOCKED.md: loop id, file, question, best guess, since |
| POST | `/api/loops/:id/answer` | `{ ok: true, commit, pushed }` | body `{ file: "BLOCKED.md", answer }`: writes the answer to task.md, deletes BLOCKED.md, commits, then pushes if it can (`pushed: false` when there is no remote or it is offline). Errors are `{ error }`: 400 bad body, 404 unknown loop, 409 demo (`"demo is read-only"`), 422 git/answer failure |
| GET | `/api/checks` | `HealthCheck[]` | Health page: `{ loopId, kind, ok, reason, proof }` |
| GET | `/api/settings` | `DashboardSettings` | `{ demo, projectsDir?, ghAccount?, defaultRunner }`; demo mode returns only `demo` and `defaultRunner`. `ghAccount` comes from `gh api user` (absent when `gh` is missing or signed out). Read-only. |
| GET | `/api/events` | SSE | first event `ready`, then `loop-updated` (data `{"id"}`), `inbox-changed`, `checks-changed` (data `{}`; reserved, not sent until health checks refresh on their own); a `: keep-alive` comment every 25 s. Real mode polls the clones every 5 s and `git fetch`es every 5 min; demo mode only sends `ready`. |

**LoopSummary (draft; server finalises it in types.ts):** `{ id, name, url?, state: LoopState, reason, round, roundsTotal, run, runLimit, nextRunAt?, tests?: { passed, failed, at }, live?: { ok, status, leaked: string[] }, pages?, lastCommit?: { sha, at, message } }`

**Lanes (round 2):** `LoopSummary` and `LoopDetail` carry optional `lanes?: LaneStatus[]` (type in `src/core/types.ts`; present only when the clone has `.ai/lanes.json`, one entry per lane in that file's order). `LaneStatus` = `{ name, state: 'building'|'waiting'|'blocked'|'done'|'stalled', run, limit, lastCommit?: { sha, subject, at }, locked, waitingOn?: string[], unanswered: { from, to, at, text }[] }`. Read by core's `readLaneStatuses`. `state` rules: BLOCKED/DONE in the lane folder or repo root win; `building` = fresh lane lock (under 90 min); `stalled` = no commit or lock for over 120 min (2 cron periods) and no stop file; else `waiting`. `unanswered` = messages to a named lane with no later outbox entry or commit from it; `waitingOn` = lanes this lane has such messages open to. `/api/checks` adds two kinds for laned loops: `lane-stalled` and `lane-waiting-on-finished` (a non-done lane waits on a done lane); a failing one turns the loop `failing` with that reason. Web's Needs-you count: any lane `blocked`/`stalled`, or any `lane-waiting-on-finished` check failing.

**Live mode (round 3):** the static site reads GitHub directly from the browser; no server. `src/server/live/` is pure and browser-safe (no `node:` imports; a test enforces it). `liveUrls(slug)` gives the commits URL (`api.github.com/repos/<slug>/commits?sha=main&per_page=100`), the Actions runs URL and the raw URLs of `BASE_FILES` (`.ai/task.md`, `.ai/lanes.json`, `DONE.md`, `BLOCKED.md`, `.ai/done-v1..9.md`); once `.ai/lanes.json` is fetched, `laneFilePaths(laneNames)` lists the per-lane files (`task.md`, `outbox.md`, `DONE.md`, `BLOCKED.md`, `claim`) to fetch from `rawUrl(slug, path)`. A 404 means "file absent": pass it as `undefined`. Then `buildLiveLoop({ slug, id?, commits, runs, files, now })` returns `{ detail: LoopDetail, inbox: InboxItem[], checks: HealthCheck[] }`, the same shapes as the `/api` routes (lanes, claims, unanswered messages, `lane-*` checks, and a `failing-tests` check from the newest finished Actions run). Author names and emails are never read. Lane locks are gitignored, so live lanes are never `building` from a lock; they read `waiting`/`stalled` from their last `Lane:` commit. The static site also serves `live.json` = `{ "repo": "Minntooos/Compounding-Loop", "loop": "compounding-loop" }` (`loop` becomes the loop id), and its `index.html` carries a CSP meta tag whose `connect-src` is `'self' https://api.github.com https://raw.githubusercontent.com` (`STATIC_CSP`, `src/server/static-export.ts`); the local server CSP is unchanged. **Round 4 history (A1):** the bundled snapshot (`demo/this-repo.json`, pinned at `SNAPSHOT_COMMIT` b3b51a5) carries the full commit history; its loop has `snapshotAt` (ISO time of its newest commit; absent on live/local data) and `LoopCommit.author` (display name, never an email). Live mode fetches only what is newer: `commitsSinceUrl(slug, snapshotSince(timeline), page)` (GitHub's `since` is inclusive), repeating with `page+1` while `hasMoreCommits(entries.length)`; concatenate the pages' JSON arrays and pass them as `commits` plus the snapshot timeline as `snapshotCommits` to `buildLiveLoop`, which merges by sha (live copy wins, newest first; `mergeCommits` is exported for direct use).

**Round 4 data fields (all optional, additive; shapes in `src/core/types.ts`):** `HealthCheck.label` (result in words: "Tests pass" / "Tests failing"; proof strings use `formatUtc`, e.g. `11 Oct 14:53 UTC`, never raw ISO); `LoopSummary.snapshotAt` (set on every bundled-snapshot loop, absent on live/local: show "snapshot 6 Oct" from it, "Live" only without it), `roundLabel` ("Round 3 done · 0.3.0" / "Round 4"; use it instead of "Round N of M"), `releaseWaiting` (laned loop with a root `DONE.md`; state is `done`, reason "... · release waiting on you"), `repoUrl` (the code repo when `url` is the site/Pages URL; live `url`/`demoUrl` come from `live.json` `pages`); for laned loops `run`/`runLimit` are the sums over the lanes (per-lane values are in `lanes[]`); `LoopCommit.author`, `LoopCommit.lane` (trailer, then subject prefix, `release` for `Release x.y.z`, else `other`); `LoopDetail.laneNotes[]` = `{lane, contract, decisions, knowledge}` per lane (grouped Contract/Decisions/Knowledge tabs; contract items read `**Done when:** a; b.` lines too); `InboxItem.kind` (`question` default | `release`): a `release` item (file `DONE.md`) has no answer form, it points at Ready to ship. `GET /api/settings` is also exported as `api/settings.json` in the static site (no more 404). `live.json` gained `pages`; `BASE_FILES` gained `package.json` (version for the labels); `buildLiveLoop` takes `pagesUrl`.

**Runs (Round 4 unit 4):** `LoopDetail.runs?: LoopRun[]` (newest first, last 48 h, max 200; `{lane, at (slot or run end), outcome: pushed|nothing-pushed|tests-failed|no-run-recorded, endedAt?, units, tests?, commits, note?}`), `nextRuns?: {lane, at}[]` (next cron slot per lane), `LoopSummary.lastRun?: {lane, at, outcome}` (fleet card line). Built by the pure `buildRuns` (`src/server/runs.ts`, exported from `src/server/live`) from each lane's `runs.jsonl` (`laneFilePaths` now includes it), `.ai/lanes.json` crons and the commits; a slot younger than 90 min is not "missing" yet; commits join a run by `Claude-Session:` (`LoopCommit.session` = last 8 characters) when both sides have one, else by the slot's time window. Three or more missing slots in a row (lane has run or committed before, is not done/blocked) add an `InboxItem` with `kind: 'lanes-not-running'` (file `.ai/lanes.json`; no answer form). The bundled self snapshot predates the run log and carries no `runs`. Local mode fills the same fields from the clone.

**Controls (Round 4 unit 5, first part):** `LoopSummary.paused?: {by, at?, reason?}` (from `.ai/PAUSED`; "Paused by X since ..." on the card); `LoopDetail.controlNotes[]` (`{lane, at, text}`, newest control-room note per lane), `releases[]` (CHANGELOG, newest first, `{version, date?, sections, items}`), `ship?` (core's `shipCheck` result, only for a laned loop with a root `DONE.md`; the live tag check needs `LiveInput.tags` = the tags API JSON). Live mode also fetches `.ai/PAUSED`, `.ai/control-room.md` and `CHANGELOG.md` (`BASE_FILES`). Pure URL builders (`src/server/controls.ts`, exported from `src/server/live`): `pauseUrl(slug, by, now, reason?)`, `resumeUrl(slug)`, `nextRoundUrl(slug, brief)`, `releaseWorkflowUrl(slug)`, `editFileUrl(slug, file)` (Inbox -> web editor), `deleteFileUrl`, `newFileUrl`, plus API URLs `latestReleaseRunApiUrl(slug)` `tagsApiUrl(slug)` (first 100 tags only) and `tagLookupApiUrl(slug, version)` (matching-refs, no cap; `LiveInput.tags` accepts either response); all throw on a bad slug or a path that leaves the repo. 
**Local actions (Round 4 unit 5, second part; local server only, demo answers 409 `demo is read-only`):** `POST /api/loops/:id/pause` body `{reason?}` -> `{ok, changed, by?, pushed?, pushError?}`; `POST /api/loops/:id/resume` `{}` -> `{ok, changed, pushed?, pushError?}`; `POST /api/loops/:id/next-round` body `{brief}` (non-empty, else 400) -> `{ok, changed, committed, pushed?}` (laned repos only; 422 with the reason otherwise). Same loopback/JSON-only/Origin guards as `answer`; commits carry `Lane: control`. Errors are 422 `{error}`. `GET /api/doctor` -> `{report, passed}` (the `loop doctor` text; the demo returns a pointer to `npx compounding-loop doctor` with `passed: true`). `laneNotes[]` on LoopDetail is the per-lane contract/decisions/knowledge web asked for as `laneDetails`. Local `readLoop` also fills `ship` (laned loop with a root `DONE.md`): tag via `git tag --list`, tree via `git status --porcelain` (a failing git call reads as tag free / tree dirty). Not yet: Search Console.

**Guard (all routes):** `Host` must be loopback (`127.0.0.1`, `localhost`, `[::1]`) and `Origin`, when sent, must be a loopback page, else `403 { error: "forbidden" }`. POSTs must send `Content-Type: application/json` (else 415). A dev proxy must keep a loopback Host/Origin. The answer text is stored as typed (the word `accept` is not a command).

**Static files:** every non-`/api` GET serves `dist/web` (unknown extension-less paths fall back to `index.html`) with a strict CSP (`default-src 'none'`, scripts/fonts/connect only from `'self'`), `nosniff` and no-referrer.

**Static demo (GitHub Pages):** `npm run build` then `node demo/export-static.mjs` writes `demo/static/api/{health,loops,inbox,checks}.json` and `demo/static/api/loops/<id>.json`, the same bodies as the live demo API. Web's static mode fetches these as *relative* URLs (`api/loops.json`, no leading slash) so a Pages sub-path works, and hides the answer form.
